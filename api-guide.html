<h1 class="font-display text-3xl text-white mb-2">JavaScript API Guide</h1>
<p class="text-[#a89dc7] mb-8">Build plugins with JavaScript or TypeScript, hot-reload on save, and access the full game-state API.</p>
<div class="docs-content prose prose-invert max-w-none">
<h2 id="overview">Overview</h2>

<p>
JavaScript plugins run inside an embedded <strong>QuickJS</strong> engine within the game process. They have
access to the same game-state queries, rendering primitives, and action APIs as native C++ plugins &mdash;
exposed through the global <code>titan</code> namespace.
</p>

<p>Key advantages of JS plugins:</p>
<ul>
<li><strong>Hot-reload</strong> &mdash; the file watcher reloads <code>.js</code> files on save, no restart needed</li>
<li><strong>No build toolchain</strong> &mdash; any text editor works; TypeScript is optional</li>
<li><strong>Rapid prototyping</strong> &mdash; iterate quickly on overlay scripts and automation helpers</li>
</ul>

<h2 id="current-sdk-concepts">Current SDK Concepts</h2>

<p>
The JavaScript API mirrors the current SDK v107 surface. Query results have fixed membership at the
moment you collect them, but entity and widget handles are live where the SDK exposes a resolver. Use
<code>.exists</code> and <code>.snapshot()</code> when you retain a handle across ticks and need to confirm or freeze
its current fields.
</p>

<ul>
<li><strong>WorldViews:</strong> locatable handles expose <code>worldViewId</code>; locatable queries support <code>.worldView(id)</code>, <code>.currentWorldView()</code>, and <code>.topLevelWorldView()</code>.</li>
<li><strong>Gamevals:</strong> generated native catalogs live under <code>titan.gamevals.*</code> alongside legacy enum helpers.</li>
<li><strong>Target-aware actions:</strong> magic casts, item use, menu invocation, and <code>titan.utils.mouse.resolveActionClickPoint</code> share the native clickbox resolver.</li>
</ul>

<h2 id="plugin-registration">Plugin Registration</h2>

<p>
Register a plugin by extending <code>titan.Plugin</code> and calling <code>titan.register()</code>:
</p>

<pre><code class="language-javascript">class MyPlugin extends titan.Plugin {
id = "my_js_plugin";
name = "My JS Plugin";
description = "A sample JavaScript plugin.";
author = "Your Name";
version = "1.0.0";

onGameTick(tick) {
if (tick % 20 === 0) {
titan.log("20 ticks passed!");
}
}
}
titan.register(new MyPlugin());</code></pre>

<p>
You can also use an object literal for simpler plugins:
</p>

<pre><code class="language-javascript">titan.register({
id: "simple_plugin",
name: "Simple Plugin",
onGameTick(tick) {
// ...
}
});</code></pre>

<h2 id="break-handler">Coordinated Breaks (<code>titan.breakHandler</code>)</h2>

<p>
SDK 97+ exposes the same instance-addressed break protocol as C++ and Java. Pass the exact plugin object
registered with <code>titan.register</code> to every call. Poll before acknowledging or reporting a command.
</p>

<pre><code class="language-js">onEnable() {
titan.breakHandler.register(this, true); // false = participant only
titan.breakHandler.start(this);
titan.breakHandler.running(this);
}

onGameTick() {
const command = titan.breakHandler.poll(this);
if (command.phase === "PREPARE") {
// While unsafe: defer(this, 600, "finishing current action").
// Once this plugin has stopped issuing actions and reached safety:
titan.breakHandler.paused(this);
} else if (command.phase === "RESUME") {
titan.breakHandler.running(this);
}
}

onDisable() {
titan.breakHandler.stop(this);
titan.breakHandler.unregister(this);
}</code></pre>

<h2 id="settings">Settings</h2>

<p>Declare settings using the builder methods on the plugin class:</p>

<pre><code class="language-javascript">class MyPlugin extends titan.Plugin {
id = "my_plugin";
name = "My Plugin";

loud = this.boolSetting({ key: "loud", name: "Verbose", default: false });
radius = this.intSetting({ key: "radius", name: "Radius", default: 10, min: 1, max: 50 });
mode = this.comboSetting({
key: "mode", name: "Mode", default: 0,
choices: [{ value: 0, label: "Off" }, { value: 1, label: "On" }]
});
filter = this.stringSetting({ key: "filter", name: "Filter", default: "Chicken" });

kills = 0;

// Value-less action button (SDK 98). onClick runs on the game thread,
// including at the login screen. Keep it non-blocking.
resetStats = this.buttonSetting({
key: "reset_stats", name: "Reset stats",
tooltip: "Zero the kill counter",
onClick: () => { this.kills = 0; },
});

onGameTick(tick) {
if (this.loud.value) {
titan.log("Radius: " + this.radius.value);
}
}
}</code></pre>

<h2 id="overlay-panels-js">Overlay panels (<code>overlayPanel</code>)</h2>

<p>
Register anchored HUD panels with <code>this.overlayPanel({ name, anchor, priority?, style?, render })</code>
from the plugin constructor. Use <code>titan.OverlayAnchor</code> for the initial anchor (e.g.
<code>titan.OverlayAnchor.AboveChatboxRight</code>). The <code>render</code> callback receives a builder with
<code>title</code>, <code>line</code>, <code>progressBar</code>, and <code>set*</code> style methods.
See <a href="/docs/panels-overlays#js-overlay-panels">Panels &amp; Overlays</a> for a full example and anchor table.
</p>

<h2 id="titan-namespace">The <code>titan</code> Namespace</h2>

<p>
The global <code>titan</code> object mirrors the C++ SDK's query, state, utils, and gamevals architecture. In JavaScript,
zero-arg primitive lookups are <strong>properties</strong> (no parentheses), while calls that take arguments,
allocate collections, or have side effects are <strong>methods</strong>.
</p>



<h2 id="state">State Facades (<code>titan.state</code>)</h2>

<p>
State facades give you read (and sometimes write) access to the game's live data. Each facade groups
related information &mdash; camera, skills, prayers, etc.
</p>

<h2 id="queries">Query Builders (<code>titan.queries</code>)</h2>

<p>

<h2 id="performance">Performance Considerations</h2>

<ul>
<li>Each JS callback has an <strong>opcode budget of 1,000,000 operations</strong>. Exceeding this interrupts the callback to prevent the game from freezing.</li>
<li>Prefer game-tick callbacks for periodic logic; avoid heavy computation in <code>onClientTick</code> or <code>onRender</code>.</li>
<li>Query result membership is a snapshot &mdash; call <code>.toArray()</code> once and iterate the result, rather than making repeated queries in a loop.</li>
</ul>

<h2 id="hot-reload">Hot Reload</h2>

<p>
The plugin host watches plugin directories for <code>.js</code> file changes. When you save a file, the
engine unloads the old script and loads the new one &mdash; preserving the plugin's enabled state but
resetting all runtime state. This happens on the game thread and is seamless during gameplay.
</p>

<p>
In Release builds, local <code>.dll</code>, <code>.js</code>, and <code>.jar</code> discovery shares one gate:
start the controller with <code>--dev-mode</code> and use an account entitled for <code>feature.debug_mode</code>.
JavaScript is not special here; all local plugin formats participate in the same disk-loading path.
</p>

<p>
<strong>Tip:</strong> Use hot-reload for rapid iteration during development. For complex state that should
survive reloads, persist it in settings rather than local variables.
</p>
