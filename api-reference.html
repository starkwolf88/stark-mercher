<h2 id="entity-types">Entity Types</h2>

<p>
Entity types are lightweight value wrappers returned by queries and facades.
They provide direct accessors into game state and convenience helpers for
interaction, distance checks, and identity comparison.
Member lists below mirror <code>shared/titan/actor.h</code> (and related headers) in the SDK repo.
</p>

<p id="locatable">
World-placed entities derive positional helpers from the <code>Locatable&lt;T&gt;</code> CRTP mixin:
<code>tile()</code>, <code>worldPoint()</code>, <code>localPoint()</code>, and <code>distanceTo(...)</code>
(see <code>shared/titan/actor.h</code>). Primitive fields such as <code>tileX()</code> / <code>worldX()</code>
are listed on each type where applicable.
</p>

<h2 id="queries">Queries</h2>

<p>
Queries are lazy, chainable pipelines created via factory functions in the
<code>titan::queries</code> namespace. Each query follows a builder pattern:
chain zero or more <strong>filter</strong> methods, then call a <strong>terminal</strong> to
materialize results.
</p>

<h3 id="query-terminals">Common Terminal Methods</h3>
<p>Every query type supports these terminal operations:</p>

<table>
<thead><tr><th>Terminal</th><th>Returns</th><th>Description</th></tr></thead>
<tbody>
<tr><td><code>count()</code></td><td><code>int</code></td><td>Number of matching entities</td></tr>
<tr><td><code>any()</code></td><td><code>bool</code></td><td>True if at least one match exists</td></tr>
<tr><td><code>empty()</code></td><td><code>bool</code></td><td>True if no matches exist</td></tr>
<tr><td><code>first()</code></td><td><code>optional&lt;T&gt;</code></td><td>First matching entity (empty if none)</td></tr>
<tr><td><code>forEach(fn)</code></td><td><code>void</code></td><td>Invoke callback for each match</td></tr>
<tr><td><code>toVector()</code></td><td><code>vector&lt;T&gt;</code></td><td>Collect all matches into a vector</td></tr>
</tbody>
</table>

<p>
Locatable queries additionally expose WorldView-aware filters such as <code>worldView(id)</code>,
<code>currentWorldView()</code>, <code>topLevelWorldView()</code>, tile/world/local-point distance filters,
and <code>within(const WorldArea&amp;)</code>.
</p>

<h3 id="services">Owned Services And Account Profiles</h3>

<p>
Use <code>titan::registerService(owner, id, pointer)</code> for SDK 97+ native service publication. The
exact plugin instance/load generation owns the entry; it survives ordinary UI disable and is removed
automatically on unload. Resolve with <code>titan::service&lt;T&gt;(id)</code>. The
<code>&lt;titan/account_profiles.h&gt;</code> contract exposes the versioned POD-only
<code>titan.account_profiles.v1</code> service for sanitized vault status, immutable profile snapshots,
and asynchronous activation begin/poll/submit/cancel operations. No credentials or runtime objects cross
that DLL boundary.
</p>
