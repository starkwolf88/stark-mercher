<h1 class="font-display text-3xl text-white mb-2">Getting Started</h1>
<p class="text-[#a89dc7] mb-8">Set up the current Titan plugin dev loop for native C++, QuickJS/TypeScript, or Java.</p>
<div class="docs-content prose prose-invert max-w-none">
<h2 id="local-loading">Local Loading Requirements</h2>

<p>
Local disk plugin loading is shared by every local plugin format. In Release builds, launch with
<code>--dev-mode</code> and use an account with the <code>feature.debug_mode</code> entitlement before
local <code>.dll</code>, <code>.js</code>, or <code>.jar</code> plugins are discovered. This is the same
gate for native, QuickJS, and Java plugins.
</p>

<p>
Third-party native and Java starter projects use DEV sessions. A DEV session stages your plugin under
<code>build/.titan/dev/&lt;slug&gt;/load/gen-N/</code>, writes <code>session.json</code>, launches the controller
with <code>--dev-mode --dev-manifest ... --launch-new-client</code>, and later Run invocations recycle only
the matching dev tab through the controller's single-instance pipe.
</p>

<h2 id="native-prerequisites">Native C++ Prerequisites</h2>

<ul>
<li><strong>Visual Studio 2022</strong> with Desktop development with C++, MSVC v143, and a Windows 10/11 SDK.</li>
<li><strong>CMake 3.24+</strong>.</li>
<li><strong>Git</strong>.</li>
<li><strong>vcpkg</strong> only when building the full TitanClient source tree; third-party plugin projects consume the public SDK helper target.</li>
<li><strong>CLion or Visual Studio</strong> with CMake support for the smoothest Run target workflow.</li>
</ul>

<div class="callout callout-warning">
<p>
<strong>CRT linkage:</strong> native plugin DLLs must use the static MSVC runtime
(<code>/MT</code> / <code>/MTd</code>). The SDK's <code>titan_add_plugin</code> helper applies this for you.
</p>
</div>

<h2 id="native-template">Native C++ Template Flow</h2>

<ol>
<li>Run TitanLauncher once so it syncs a TitanClient runtime under <code>%USERPROFILE%\.titanclient\repository</code>.</li>
<li>Clone the SDK once per machine and set <code>TITAN_PLUGIN_SDK_ROOT</code>.</li>
<li>Create a plugin from the Titan native plugin template, rename the slug, open it in your IDE, and run the generated <code>titan_run_&lt;slug&gt;</code> target.</li>
</ol>

<pre><code class="language-powershell">git clone https://github.com/Soxs/titan-plugin-sdk C:/sdks/titan-plugin-sdk
setx TITAN_PLUGIN_SDK_ROOT C:/sdks/titan-plugin-sdk</code></pre>

<p>
Set <code>TITAN_CLIENT_ROOT</code> only when you want to target a custom/source-built runtime instead of
the latest launcher-synced runtime.
</p>

<pre><code class="language-powershell">setx TITAN_CLIENT_ROOT C:/path/to/TitanClient/runtime</code></pre>

<h3 id="native-cmake">CMakeLists.txt</h3>

<pre><code class="language-cmake">cmake_minimum_required(VERSION 3.24)
project(my_plugin LANGUAGES CXX)

set(TITAN_PLUGIN_SDK_ROOT "$ENV{TITAN_PLUGIN_SDK_ROOT}" CACHE PATH "")
set(TITAN_CLIENT_ROOT "$ENV{TITAN_CLIENT_ROOT}" CACHE PATH "")

add_subdirectory(${TITAN_PLUGIN_SDK_ROOT} titan_sdk EXCLUDE_FROM_ALL)

titan_add_plugin(
TARGET my_plugin
SLUG my_plugin
SOURCES my_plugin.cpp
)

titan_add_dev_session(
PLUGIN my_plugin
LOADER_MODE DebuggableLoadLibrary
)</code></pre>

<h3 id="native-source">Plugin Source</h3>

<pre><code class="language-cpp">#include &lt;titan/plugin.h&gt;
#include &lt;titan/client.h&gt;
#include &lt;titan/query.h&gt;
#include &lt;titan/render.h&gt;
#include &lt;titan/setting.h&gt;
#include &lt;titan/utils/inventory.h&gt;

class MyPlugin : public titan::Plugin {
TITAN_PLUGIN_META(
"my_plugin",
"My Plugin",
"Shows how to wire up a native Titan plugin.",
"Your Name",
"1.0.0",
false)

public:
titan::BoolSetting loud{this, "loud", "Verbose logging", false};

MyPlugin() {
onRender(titan::Layer::AboveScene, [this] { drawWorld(); });
}

void onGameTick(int32_t tick) override {
if (loud && tick % 10 == 0) {
titan::logf("tick=%d invFull=%d",
tick,
titan::utils::Inventory::isFull() ? 1 : 0);
}
}

private:
void drawWorld() {
auto local = titan::state::client().localPlayer();
if (!local) return;
titan::queries::npcs()
.nameContains("Chicken")
.forEach([](const titan::Npc& n) {
titan::overlay().entityBox(n, 0xFF00FF00);
});
}
};

TITAN_REGISTER_PLUGIN(MyPlugin, "my_plugin")</code></pre>

<h3 id="loader-modes">DEV Loader Modes</h3>

<table>
<thead><tr><th>Mode</th><th>Use case</th></tr></thead>
<tbody>
<tr><td><code>DebuggableLoadLibrary</code></td><td>Default day-to-day mode. Loads the staged DLL from disk and resolves breakpoints through the co-located PDB.</td></tr>
<tr><td><code>Restart</code></td><td>Compatibility alias for the same current load primitive.</td></tr>
<tr><td><code>MemoryBlob</code></td><td>Smoke-tests production-style in-memory mapping through PerfectLoader with MemoryModulePP fallback. Breakpoints do not resolve naturally.</td></tr>
</tbody>
</table>

<h2 id="javascript-quickstart">QuickJS / TypeScript Quickstart</h2>

<p>
QuickJS plugins are JavaScript files loaded by the embedded script engine. TypeScript is optional; use
<code>titan-plugin-sdk.d.ts</code> for typing and compile to a <code>.js</code> output file.
</p>

<pre><code class="language-javascript">class MyPlugin extends titan.Plugin {
id = "my_js_plugin";
name = "My JS Plugin";
description = "JS version of the hello-world sample.";
author = "Your Name";
version = "1.0.0";

loud = this.boolSetting({
key: "loud",
name: "Verbose logging",
default: false
});

onGameTick(tick) {
if (this.loud.value && tick % 10 === 0) {
const full = titan.utils.inventory.isFull ? 1 : 0;
titan.logf("tick=%d invFull=%d", tick, full);
}
}

world = this.overlay({
layer: titan.OverlayLayer.ABOVE_SCENE,
render: () => {
const local = titan.state.client.localPlayer;
if (!local) return;
titan.queries
.npcs()
.nameContains("Chicken")
.forEach((n) => titan.overlay.entityBox(n, 0xff00ff00));
}
});
}

titan.register(new MyPlugin());</code></pre>

<p>
Place the compiled <code>.js</code> in a local plugin scan directory. When local disk loading is enabled,
the file watcher hot-reloads changed scripts while preserving the plugin enabled state.
</p>

<h2 id="java-quickstart">Java Quickstart</h2>

<p>
Java plugins are JARs loaded by the embedded JVM in <code>client.dll</code>. Standalone Java projects should
use the Gradle dev plugin workflow and the public <code>net.titan:titan-plugin-api</code> dependency.
</p>

<pre><code class="language-gradle">plugins {
id 'java'
id 'net.titan.dev' version '0.1.1'
}

repositories {
maven { url = uri('https://raw.githubusercontent.com/Soxs/titan-public-sdk/main/maven/releases') }
mavenCentral()
}

dependencies {
compileOnly 'net.titan:titan-plugin-api:latest.release'
annotationProcessor 'net.titan:titan-plugin-api:latest.release'
}</code></pre>

<pre><code class="language-powershell">.\gradlew.bat runViaTitan
.\gradlew.bat runViaTitanDebug</code></pre>

<p>
<code>runViaTitan</code> stages the JAR and launches a DEV tab. <code>runViaTitanDebug</code> enables JDWP
on localhost, defaulting to port <code>5005</code>.
</p>

<h2 id="plugin-identity">Plugin Identity</h2>

<p>
Every plugin has a permanent unique id: the first argument to <code>TITAN_PLUGIN_META</code>, the
JavaScript <code>id</code> property, or the Java <code>&#64;PluginDescriptor(id = ...)</code> value.
The controller uses this id for settings, enabled state, dependencies, and store/build metadata.
</p>

<div class="callout callout-warning">
<p>
<strong>Never change a published plugin id.</strong> Changing it orphans user settings and enabled state.
Treat the id as permanent; change the display name instead.
</p>
</div>
